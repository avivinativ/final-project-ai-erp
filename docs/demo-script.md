# תסריט דמו (כ-7 דקות)

לפני כל דמו: הרץ ידנית **WF6** ואז **WF7** ב-n8n (Execute workflow) — המאגר הווקטורי מתאפס בכל
הפעלה מחדש של השרת. ודא ש-WF1, WF3, WF4b, WF5, WF8, WF9, WF13 פעילים (WF4a נשאר כבוי בכוונה).

## 1. הצגת הארכיטקטורה (דקה אחת)
פתח את [docs/architecture.md](architecture.md) והראה את שלוש השכבות: Airtable (נתונים),
n8n (10 workflows + WF0 error handler), Next.js (ממשק). הדגש: נקודת הכתיבה היחידה מהאפליקציה
ל-Airtable היא webhook אחד (WF13) — ה-PAT של Airtable לא נחשף לדפדפן.

## 2. דשבורד + יצירת ליד (דקה וחצי)
`npm run dev` בתוך `app/`, פתח את הדפדפן. עבור לעמוד הלידים, צור ליד חדש. תוך כדקה WF3
(Airtable trigger, כל דקה) יתפוס אותו ויסמן `New`. רענן ותראה את הסטטוס מתעדכן — הוכחה חיה
שהאוטומציה רצה ברקע בלי מגע יד.

## 3. חשבונית מקצה לקצה (2 דקות)
מהאפליקציה, צור חשבונית עם `CustomerId` ו-`Amount`. הראה בזמן אמת:
- WF1 (כל דקה) מחשב מע"מ, סה"כ ומספר חשבונית (`INV-` + timestamp), מסמן `ValidatedQueued`.
- WF8 (כל דקה) בונה HTML בעברית, מעלה לגוגל דרייב, מסמן `Invoiced` ומצרף `PdfUrl`.
פתח את הקובץ שנוצר בדרייב כדי להראות עיצוב RTL תקין.

## 4. בוט שירות לקוחות (דקה וחצי)
פתח את בוט הטלגרם ללקוחות ושאל: "מה מדיניות ההחזרות שלכם?" ו"יש לכם רמקול בלוטות'?". הסוכן
עונה על סמך RAG בלבד (מדיניות + מוצרים אמיתיים מ-Airtable) — אם תשאל על משהו שלא קיים במאגר,
הוא יפנה לנציג אנושי במקום להמציא תשובה.

## 5. בוט מנהל (דקה אחת)
פתח את בוט הטלגרם של המנהל ושאל "מה ההכנסות שלי?" — הסוכן שולף עד 100 חשבוניות אחרונות
ועונה על סמך הנתונים בלבד. נסה לשלוח הודעה מחשבון טלגרם אחר (לא ה-chat id הקבוע) כדי להראות
את חסימת הגישה.

## 6. טיפול בשגיאות (חצי דקה)
הראה את WF0 ב-n8n ואת ה-Error Workflow המוגדר בהגדרות של אחד מה-workflows. אפשר להדגים כשל
אמיתי (למשל לנתק זמנית קרדנציאל) ולהראות שהתראת הטלגרם מגיעה למנהל.

## נקודות סיכום
- כל הלוגיקה בצמתים מוכנים של n8n, אפס קוד בצד השרת של האוטומציה.
- כל node בכל workflow מתועד ב-sticky note בעברית — הקנבס מסביר את עצמו.
- הדשבורד הוא קוד Next.js אמיתי (לא no-code), עם קריאות Airtable ישירות לקריאה וכתיבה
  דרך n8n בלבד.
